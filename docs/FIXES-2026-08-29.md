## P0 — 壊れていたもの

### 1. `.mrpack` の `env.client` が誤っていた（最重要）
`src/services/mrpack.js`

Modrinth の**プロジェクト属性** `client_side` / `server_side` を、mrpack の**インストール指示** `env` にそのままコピーしていた。この2つは意味が違う。プロジェクト側の `"optional"` は「必須ではないが動く」、mrpack 側の `"optional"` は「このパックでは任意＝ランチャーが省いてよい」。結果、画面に「N個書き出しました」と出ながら実際には入らないMODが発生していた。

```diff
-function envValue(v) {
-  return v === "optional" || v === "unsupported" ? v : "required";
-}
+function envFor(mod) {
+  return {
+    client: mod.client_side === "unsupported" ? "unsupported" : "required",
+    server: mod.server_side === "unsupported" ? "unsupported" : "required",
+  };
+}
```

あわせて、クライアントで動かないMOD（サーバー専用）の件数を書き出し後のメモに表示するようにした。

### 2. 成立しないバージョン × ローダーをブロック
`src/data/loaderSupport.js`（新規） / `src/components/Filters.jsx` / `src/App.jsx`

Fabric ≥1.14、Quilt ≥1.18.2、NeoForge ≥1.20.1 を持ち、非対応のローダーはボタンを `disabled` にして理由をツールチップ表示。バージョンを変えて現在のローダーが非対応になった場合は自動で切り替え、その旨をメッセージで通知する。判定できないバージョン（スナップショット等）はブロックしない。

### 3. 生成後の無反応を解消
`src/App.jsx`

生成完了時に結果セクションへ `scrollIntoView`（`prefers-reduced-motion` を尊重）。ローディング表示・ボタンの `disabled`・文言変更は既存実装を維持。

### 4. ルート別の canonical / title / description
`src/utils/seo.js`（新規） / `scripts/prerender.mjs`（新規） / `index.html`

すべてのページが `canonical` でトップを指し、title も description も同一だった（＝下層ページを「トップの複製」と宣言していた）。

- クライアント側: ルート遷移のたびに title / description / canonical / OGP / JSON-LD を差し替え
- **ビルド時**: `vite build` の後に `scripts/prerender.mjs` が `dist/guide/index.html` などを実ファイルとして出力。クローラが最初に読むHTMLの時点で各URLが自己記述的になる
- JSON-LD: `WebApplication` ＋ `BreadcrumbList`（下層）＋ `FAQPage`（/guide）

### 5. プライバシーポリシーと実装の矛盾を解消
`src/components/Privacy.jsx` / `src/data/siteConfig.js`

「※ 現時点では広告は掲載していません」と書きながら AdSense スクリプトを全ページで読み込んでいた。`SITE_CONFIG.adsStatus`（`pending` / `live` / `off`）で記述が実態に追従するようにし、現在は「審査・準備段階で広告枠は表示していないが、ローダースクリプトは読み込んでいる」と明記。EEA向けCMPについても「予定」ではなく運用方針として記載。

### 6. お問い合わせ窓口
`src/components/Contact.jsx` / `src/data/siteConfig.js`

`contactFormUrl` / `contactEmail` / `githubUrl` / `xUrl` のいずれかを埋めればボタンが出る構成にした。**まだ空**なので、下記「残作業」を参照。

## P1 — 体験の穴

### 7. 選定アルゴリズムの品質ゲート
`src/data/curated.js`（新規） / `src/utils/packBuilder.js`

「カテゴリ検索 → DL数降順 → 上位N件」だけだったため、`技術・自動化` にシェーダーアドオン、`魔法` にDL1.2Kのネタ MOD、`軽量化` にクラッシュログビューアが入っていた。以下を追加:

| ルール | 内容 |
|---|---|
| 最低DL数 | 10万（充足しない場合のみ2万に緩和） |
| キュレーション | 13ロール分の推奨MODリスト（slug指定）。該当MODは順位を優先し、DL数の下限も免除 |
| 除外リスト | シェーダーアドオン、シェーダーローダー、デバッグ補助、ネタMOD |
| ライブラリ除外 | `library` タグのMODは採用枠に入れない（依存解決でのみ追加） |
| サーバー専用除外 | `client_side: "unsupported"` のMODは採用しない |
| カテゴリ純度 | `performance` 以外のロールで `optimization` タグのMODを除外 |

slug で照合しているため、綴りが違ったり名称変更されたMODは**単に一致しないだけ**でビルドは壊れない。

### 8. 警告の作り直し
`src/data/warnings.js`

カテゴリタグから機械生成していたため、事実でない警告が出ていた（Sodium / Iris / FerriteCore を「競合するので1つに絞れ」など）。

- `optimization` カテゴリ由来の一括警告を**削除**
- 「前提ライブラリ」警告は、**実際に依存解決で自動追加したMOD**だけを対象に変更
- ハード競合DBを拡張（Sodium×Embeddium / Sodium×Rubidium / Iris×Oculus を追加）
- 重複検知を新設: レシピ表示MOD（JEI/EMI/REI）、マップMOD、大規模ストレージMODが複数入ったときだけ通知（Xaero's Minimap + World Map の併用は正常なので通知しない）

### 9. 構成の保存・共有
`src/utils/urlState.js`（新規） / `src/App.jsx` / `src/components/PackSummary.jsx`

`?v=1.21.1&l=fabric&t=adventure,tech&q=&perf=1&mods=create,jei,sodium` を `history.replaceState` で反映。

- 「この構成のリンクをコピー」ボタンを DL ボタンの横に追加
- `mods=` がある場合は**検索を再実行せず**、その slug 群からパックを再構築（＝共有相手が同じ構成を見る）
- 直近の条件を `localStorage` に保存し、次回訪問時に復元
- Modrinth のバージョン一覧も `localStorage` に24時間キャッシュ（ルート遷移のたびの再取得を停止）

### 10. DL直下の導入案内を主役化
`src/components/PackSummary.jsx`

10px・コントラスト2.6:1 だった1行を、**14px の番号付き3ステップ**に格上げ。Modrinth App / Prism Launcher へのリンク、必要メモリの目安、ガイドへの導線を追加。DLボタンには**件数と合計サイズ**を表示。

### 11. 条件変更時の stale 検知
`src/App.jsx` / `src/utils/packBuilder.js`

条件のシグネチャを比較し、変更されていれば「条件が変更されています」バーを表示して**DLボタンを無効化**。以前は 1.7.10 のパックを表示したままバージョンだけ変えて、そのまま古いパックを落とせてしまった。

### 12. robots.txt / sitemap.xml / 404 / OGP
`public/`

- `robots.txt`（sitemap宣言つき）と `sitemap.xml` を新規作成
- `_redirects` の `/* → /index.html 200` を廃止。既知ルートはプリレンダした実ファイルが応答し、未定義URLは `/404.html` を **HTTP 404** で返す（ソフト404の解消）
- `404.html` をサイトのデザインで新規作成
- `og-image.png`（1200×630）を作成し、`og:image` / `twitter:image` を有効化

## P2 — 品質と資産

### 13. MOD説明の日本語化
`src/data/modNotes.js`（新規・105件）

Modrinth の説明は英語しか返らないため、日本語UIなのにMODの説明だけ英語という状態だった。主要MOD105件に日本語の1行説明を用意し、未収録のMODは英語原文にフォールバック（`lang` 属性も切り替え）。**このデータが、APIを叩くだけのクローンには真似できない唯一の資産**なので、継続的に追加することを推奨。

### 14. 採用理由の書き直し
`src/utils/packBuilder.js`

全MODで同一文型（「人気の◯◯系MOD（DL 1.2K）」— 1.2Kを「人気」と書いていた）だった定型文を、キュレーション済みなら「◯◯の定番MODとして選定」、そうでなければ「◯◯カテゴリでダウンロード数が多いため採用」と、**根拠を正確に**述べる文言に変更。

### 15. MODの追加機能
`src/components/AddModBox.jsx`（新規） / `src/utils/packEdit.js`

「外す」「入れ替え」しかなく、「Create は絶対入れたい」という最も自然な要望に応えられなかった。Modrinth のインクリメンタル検索から指名追加でき、依存も自動解決する。

### 16. 軽量化MODの強制追加をやめた
`src/components/Filters.jsx` / `src/utils/packBuilder.js`

選んでいないのに毎回4つ入っていたものを、**既定ONのチェックボックス**として可視化。あわせて、こだわりキーワードが軽量化の検索にも適用されていた問題（「ドラゴンな軽量化MOD」を探しに行っていた）を修正し、テーマ検索だけに適用するようにした。

### 17. タイポグラフィ・コントラスト・タップ領域
全コンポーネント

- 10px / 11px の文字を**全廃**（最小12px、本文は13〜14px）
- `text-stone-500` / `600` を `300` / `400` に引き上げ、WCAG AA 未達の15箇所を解消
- 操作要素を `min-h-11`（44px）に統一。**モバイル390pxで40px未満のボタン0個**を自動テストで担保
- MODカードのグリッドに `md:` / `xl:` を追加（従来は640px以上すべて同一レイアウト）

### 18. アクセシビリティ
`src/components/Filters.jsx` ほか

- ローダー群を `role="radiogroup"` + `role="radio"` + `aria-checked`、テーマ群を `aria-pressed` に
- 選択状態に**チェックアイコン**を追加（色以外の手がかり）
- `<select>` / `<input>` に `id` と `<label for>` を付与
- フォームを `<form onSubmit>` で包み、**キーワード欄での Enter 送信**を有効化
- 下層ページの「ホーム」を `<button>` から `<a href="/">` に（クロール可能・新規タブ可）
- 操作ボタンに `aria-label`（「◯◯ を構成から外す」）

### 19. FAQ と構造化データ
`src/components/IntroSection.jsx` / `src/utils/seo.js`

トップに6問のFAQを追加（.mrpackとは / ダブルクリックで開かない / 統合版 / 既存ワールド / メモリ / 料金）。`/guide` には `FAQPage` の JSON-LD を出力。
